bdi 0.2.0

Minor release, **0.1.0 → 0.2.0**.

## Highlights

**The first release to carry macOS binaries.** A Mac with neither `cargo` nor
Nix now has a way in. Take `bdi-aarch64-apple-darwin` for an Apple silicon Mac
or `bdi-x86_64-apple-darwin` for an Intel one, with a `.sha256` beside each.
They are not signed by Apple, so read *Taking a macOS binary* below before the
first run.

**The inbound socket's name is kept to the user who bound it.** `bdi` reads
every directory on the way down to the socket, and where one of them is a
directory somebody else may take a name in, it no longer binds there. It names
that directory on stderr and polls instead. A run that was binding under such a
path keeps working and gets slower.

**You can say where the socket goes.** A `socket` key under `[changes]` in the
config, or `--socket` for a single run. 0.1.0 derived the path from
`$XDG_RUNTIME_DIR` and offered no way to name another, so a Mac had no channel
at all and polled every project.

## Taking a macOS binary

Gatekeeper decides on a `com.apple.quarantine` attribute that whatever
downloaded the file puts on it, and a browser puts one on — so a binary
downloaded from this page is refused until the attribute is cleared. Clear it
before the first run rather than after a refusal:

```console
$ chmod +x bdi-aarch64-apple-darwin
$ xattr -d com.apple.quarantine bdi-aarch64-apple-darwin
$ ./bdi-aarch64-apple-darwin --version
```

`curl` puts no such attribute on, so a binary fetched from a terminal takes the
same steps without the `xattr` one:

```console
$ curl -fLO https://github.com/CodeForBreakfast/beady-eye/releases/download/v0.2.0/bdi-aarch64-apple-darwin
$ chmod +x bdi-aarch64-apple-darwin
$ ./bdi-aarch64-apple-darwin --version
```

A `.sha256` sits beside each one, and it names the file it is for, so keep that
name to check it:

```console
$ shasum -a 256 -c bdi-aarch64-apple-darwin.sha256
```

Move it somewhere on your `PATH` under the name `bdi` and the README reads as
written.

Nothing has executed these binaries beyond `bdi --version`, run on the runner
that built each one.

## The other ways in

`cargo install beady-eye` from crates.io. Or pin
`github:CodeForBreakfast/beady-eye/v0.2.0` as a flake input and take either the
package or the overlay. The crate is `beady-eye`; the command it installs is
`bdi`.
