bdi 0.21.0

Minor release, **0.20.0 → 0.21.0**.

## Highlights

**The view, `bdi --json` and `bdi --beads` read through a running `bdi listen`.** Where a listener runs, they take each project's beads from it and run no `bd` of their own, so a call in a loop costs a fraction of a read. A project the listener does not answer for is read with `bd` as before, and so is every project when no listener runs. A one-shot's `generated_at` is the moment the listener last read the project. In the view, `^R` asks the listener to read every project again. A run uses only a socket that belongs to you, and takes a project's answer only where the listener's config gives that project the same path and environment command as yours. To use it, run `bdi listen` under your service manager. "Running the listener" in `docs/configuration.md` has a systemd user unit and a launchd agent. Without a listener there is nothing to do.

**`bdi listen` sends beads to anything that watches them.** A connection sends `watch` with a project, or with a project and a bead id, and is sent each bead as a line of JSON, first as it stands and then each time it changes. An alive line comes every 20 seconds. The README has a worked consumer, and `docs/design.md` has every line under "Watching".

**A read without a listener is cheaper.** bdi keeps each project's `direnv exec .` capture between runs and reuses it while direnv says it is current. `bdi --beads` reads finished beads without their descriptions and notes, and bdi holds each bead's text once. On a large tracker this takes about a second off a read and roughly halves its memory. The answers are unchanged apart from `generated_at`. The capture can hold a tracker's password, so it is kept in a file only you can read under `~/.cache/beady-eye/environments`. Delete that directory to clear it.

**A focused bead keeps its focus through a failed read.** Focus ends only when the bead's tracker answers without it. While the tracker fails, the focus stays and a line where the bead's row was says why it is missing. A bead named on the command line is never let go.

## Maintenance

The README links to beady-eye's page on codeforbreakfast.co, the design records why a shared read-only tracker user was declined, and the listener tests are steadier.
