bdi 0.44.0

Minor release, **0.43.1 → 0.44.0**.

## Highlights

**`bdi web` can show only the projects you name.** `--project` and `--all-projects` choose what the page reads, as they do for the terminal view, so one config file can serve a page for a single tracker.

**`bdi web` picks up an edit to its config without a restart.** Open pages redraw to the new config a couple of seconds after you save it. A config that will not load leaves the old one in force, and `bdi web` says so on stderr.

**`bdi web` keeps its trackers current as the terminal view does.** It polls as `poll`, `--poll` and `--no-poll` say, and hears producers on the socket that `[changes]` or `--socket` names. In a container, name a socket in `[changes]` if producers are to reach it, because `bdi web` otherwise only polls there.

**`bdi web` can open on the ready list or on chosen trees.** `--ready` opens the page on the ready list. Beads named on the command line, written `<project>:<bead-id>`, open it on their trees. An address that names its own list or tree still opens on that.

**The web page draws rows as `[row]` and `[[badges]]` say.** An open bead's id takes the colour that `open_id` names, and a row leaves out the status mark or the id where `[row]` leaves it out. A badge with a `short` form shows that form wherever the whole badge would be cut.

**`bdi web` refuses an option it cannot honour, and says why.** `--json`, `--beads` and the options that narrow `--beads` are refused, because `bdi web` serves a page rather than printing. `bdi web --help` lists the options it shares with the terminal view under a heading of their own.

## Maintenance

The terminal view and `bdi web` now share the code that reads trackers and picks up a config edit.
