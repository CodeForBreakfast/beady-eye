bdi 0.29.0

Minor release, **0.28.0 → 0.29.0**. Nothing needs changing to upgrade unless you rely on polling a project that a producer covers.

## Highlights

**A producer replaces a project's poll.** The first `covered <project>` line on the socket stands that project's poll down for the rest of the run, and from then on bdi reads the project once each burst of reports settles. A project that says nothing about `poll` behaves this way. Set `poll = true` to keep a covered project polling, which is how to check a producer you suspect.

**The foot says which projects a view reads for itself.** Where your config reaches a project differently from the watcher's, the view reads that project with bd rather than through the watcher, and the foot now names it. `--json` carries the same projects as `unanswered_by_the_watcher`.

**`bdi gates` reads a tracker only when it changed.** Given `--socket`, it takes the producer lines a view takes, and once a producer covers a project it reads that tracker only when the producer says it changed. It now takes `poll`, `--poll` and `--no-poll` the way a view does. A `poll = false` tracker is read once at start and then only when a producer reports it, so where nothing reports it, `bdi gates` never sees a gate written there afterwards.

**`bdi gates` closes a timer gate at its deadline.** A timer gate closes its timeout after it was made, and one whose deadline passed while `bdi gates` was down closes on the first look. Only a `bdi gates` with no `owners` list closes timer gates, so where two split the work by owner, the one naming `excluded_owners` closes them.

**`bdi gates` no longer reports a tracker with no open gates as a parse failure.**
