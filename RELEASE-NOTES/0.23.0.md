bdi 0.23.0

Minor release, **0.22.0 → 0.23.0**.

## Highlights

**`bdi gates` settles the beads that wait on pull requests.** Record a bead's wait on a pull request as a beads `gh:pr` gate, with the repository in the gate's `repo` metadata. `bdi gates` looks at every configured project's open gh:pr gates once a minute by default and asks GitHub through `gh` where each pull request stands. A merge closes the gate, so the bead it held back becomes ready. A close without a merge leaves the gate open and comments once on the bead it holds back. `[gates] owners` keeps an instance to the repositories of the owners it names. Given `--listen` and a webhook secret, it also takes GitHub's signed `pull_request` deliveries and settles a pull request within seconds of it moving. It needs `gh`, signed in to an account that can see those repositories. To use it, run it under your service manager. "Settling pull-request gates" in `docs/configuration.md` has a systemd unit, the webhook setup and every line it prints.

**A gh:pr gate is drawn under the bead it blocks, linked to its pull request.** A gate that cannot name its pull request is still drawn, with a note saying what is missing. `bdi --json` carries the gate's `repo`, `await_id` and `url` under `pull_request`, and `bdi --beads` lists an open gate as a bead of type `gate` that is never ready. Nothing to do.

**`bdi --beads` carries each bead's `created_at` and its whole `metadata`,** as the tracker holds them. No other field changes.
