bdi 0.36.0

Minor release, **0.35.1 → 0.36.0**.

## Highlights

**The bead window lists the beads its description names.** Each bead id the description mentions gets a row in a new `MENTIONS` section at the bottom of the window. You can follow it with Enter or a click, as you would a parent or a dependency.

**The bead window says the date a deferred bead comes back.** It sits on its own row under the bead's other dates.

**Open beads' ids can have a colour.** `bd` gives open beads no colour, so a mostly open tracker reads as one tone. Set `open_id = "identity"` under `[row]` to draw open ids in `bd show`'s blue. Without it nothing changes.

**A dependency on `<project>:<id>` now waits on that project's bead.** A bead waiting on another project's bead used to read as ready. It now waits on the bead in the project named, even where another project holds the same id. A project name your config does not list is reported as unconfigured.

**`bdi gates` closes a gate when your token cannot read the merge commit.** A fine-grained token with Pull requests read and no Contents read used to leave the gate open after its pull request merged.

**`bdi gates` no longer reports failed checks for a run that was cancelled and re-run.** A push or a title edit cancels the running checks, and only the re-run now counts.

**Deeply nested trackers no longer crash bdi or eat memory.** A tracker nested thousands of beads deep could abort bdi, and one whose blockers loop back through the nesting took gigabytes and seconds to draw. Both are now quick.

**The watcher keeps retrying a tracker it could not reach.** It used to report the failure until the tracker next changed, which on a quiet tracker could be days.

**The watcher no longer reports a bead created moments ago as gone.** It waits for a read taken after the watch before it says so.

## Upgrading

**Set `events_journal = true` on a project to have `bdi bd` and `bdi gates` write to bd's events journal.** bdi does not pass on a `BD_EVENTS_JOURNAL` you export yourself, so without the key their writes stay out of the journal and the watcher never hears of them.

**A project whose `.envrc` direnv will not load is now unavailable.** That covers an `.envrc` you ran `direnv deny` on, and a project configured with `direnv exec .` that has no `.envrc` at all. Allow the `.envrc`, or drop `direnv exec .` from that project's config. bdi used to read such a project with whatever `bd` and credentials it was started with.

**bdi's environment cache no longer holds the variables of the shell that started it.** Only what a project's `.envrc` sets is kept. The cache rebuilds itself, and you need do nothing.

## Maintenance

Dependency bumps, faster CI, steadier tests and internal tidying.
