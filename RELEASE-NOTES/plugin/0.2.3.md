beady-eye plugin 0.2.3

Patch release, **0.2.2 → 0.2.3**.

## Highlights

**The plugin's pages say what beady-eye is now.** The npm page and the marketplace listing say the plugin wakes a session when a watched bead changes status, becomes ready, is commented on, or leaves or returns to its tracker, and that beady-eye shows you, live, what every agent is doing across your projects.

**The session hears when a watch cannot be kept.** A watch or unwatch that cannot be written to disk is refused with the reason, and the watch set stays as it was. If the session's kept watches file cannot be read, it is moved aside and the session gets a `watches="unreadable"` block saying where it went. Watches made before the session's id was known that then fail to save arrive as a `watches="unkept"` block.

**The watcher's state is reported more exactly.** `watching` says the watcher has not answered yet until it first answers. A bdi config that cannot be read, a socket the plugin does not trust, and a project the watcher refused are each told with their own reason, rather than as "no project holds the bead" or "nobody is listening".

**A coming release can be tried as a candidate.** Before a release, a candidate such as `0.2.4-rc.1` can be published to npm under the `next` dist-tag and tagged as a GitHub prerelease. A marketplace pinned to a release keeps installing that release, so nothing changes unless you pin the marketplace to a candidate's tag.

**Updating.** Pin the marketplace to `plugin-v0.2.3` as the README shows, and update the plugin.

## Maintenance

Dependency bumps, and internal rework of how the plugin holds watches and decodes what the watcher sends.
