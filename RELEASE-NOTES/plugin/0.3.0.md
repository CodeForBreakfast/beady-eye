beady-eye plugin 0.3.0

Minor release, **0.2.4 → 0.3.0**.

## Highlights

**bdi shows which agents are watching a bead.** Each `watch` now tells the watcher which Claude Code session asked for it. From bdi 0.37.0, the bead's row ends in `◉` and the bead window names the agent watching it. With an older bdi, watches work as they did, so you can upgrade the plugin and bdi in either order.

**Watches stay with a session through `/clear` and `/resume`.** After either, the plugin moves the session's watches over to it the next time the session uses `watch`, `unwatch` or `watching`. Resuming that session later brings them back. A conversation you `/resume` inside a session also gets back the watches it had.

**The session hears when a watch has stopped.** If the watcher stops watching a bead it had taken, for instance because the bead's project left the bdi config, the session is sent a `watch="refused"` message naming the bead and the reason, so it can stop waiting.

**A bead that leaves its tracker is reported with `gone="true"`.** The message carries no status or readiness, so it is no longer mistaken for a bead whose own status is called `gone`. The plugin's instructions tell the session how to read it, so there is nothing to do.

**`watch` says more plainly why it refused.** A `watch` with no project names each project whose tracker it cannot reach, and why. An unreadable bdi config, or an empty watcher socket in it, is reported as a broken config naming the file, not as a watcher that is down.

**Smaller fixes.** A session is no longer told the watcher is back from an outage it never heard about. A project name or bead id holding a space character the watcher would split on is refused at once. The plugin's hook no longer fails a tool call when Claude Code hands it `null`.

## Maintenance

Dependency bumps, tests and tidying.
