bdi 0.3.0

Minor release, **0.2.0 → 0.3.0**.

## Highlights

**The first release to carry Linux binaries.** A Linux machine with neither `cargo` nor Nix now has a way in. Take `bdi-x86_64-unknown-linux-musl` on an Intel or AMD machine or `bdi-aarch64-unknown-linux-musl` on an arm64 one, with a `.sha256` beside each. They are linked statically against musl, so they depend on nothing the distribution has to supply.

`bdi` itself is unchanged, so there is nothing to do on an existing install.

## Taking a Linux binary

`uname -m` says which one you want: `x86_64` takes the first, `aarch64` the second.

```console
$ curl -fLO https://github.com/CodeForBreakfast/beady-eye/releases/download/v0.3.0/bdi-x86_64-unknown-linux-musl
$ chmod +x bdi-x86_64-unknown-linux-musl
$ ./bdi-x86_64-unknown-linux-musl --version
```

A `.sha256` sits beside each binary, and it names the file it is for, so keep that name to check it:

```console
$ curl -fLO https://github.com/CodeForBreakfast/beady-eye/releases/download/v0.3.0/bdi-x86_64-unknown-linux-musl.sha256
$ sha256sum -c bdi-x86_64-unknown-linux-musl.sha256
```

Move it somewhere on your `PATH` under the name `bdi` and the README reads as written.

Nothing has executed these binaries beyond `bdi --version`, run on the runner that built each one.

## Taking a macOS binary

The two Darwin binaries are here as well. They are not signed by Apple, so a copy a browser downloaded carries a `com.apple.quarantine` attribute and macOS refuses to run it until you clear it:

```console
$ xattr -d com.apple.quarantine bdi-aarch64-apple-darwin
```

`curl` puts no such attribute on, so a binary fetched from a terminal needs only the `chmod`.

## The other ways in

`cargo install beady-eye` from crates.io. Or pin `github:CodeForBreakfast/beady-eye/v0.3.0` as a flake input and take either the package or the overlay. The crate is `beady-eye`; the command it installs is `bdi`.

## Maintenance

- A merge to `main` that bumps the version is what cuts a release. The workflow tags, publishes to crates.io and announces from `RELEASE-NOTES/<version>.md`, and nobody pushes a tag by hand.
- The run refuses a bump that arrives without its notes file, and a `main` that declares a version nobody released.
- The Release body is a file somebody wrote, rather than a changelog generated from commit subjects.
- A check holds the README's flake pin to the version `Cargo.toml` declares.
