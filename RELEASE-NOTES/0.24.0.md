bdi 0.24.0

Minor release, **0.23.0 → 0.24.0**. It changes how a gh:pr gate's link to its pull request is drawn, so read the first highlight before you upgrade.

## Highlights

**A gh:pr gate's pull-request link now comes from a `[[badges]]` entry.** Before, `bdi` drew it unasked. Now a gate has no pull-request badge unless your config has the entry the README gives, and `bdi --json` no longer carries a `pull_request` field. Add the README's gh:pr entry to your config to keep the link.

**A badge can draw only where its bead's fields match.** A `[[badges]]` entry takes `when` and `unless` patterns over the bead's fields, and its templates can place any field of the bead. A list such as `labels` is tested a member at a time.

**A badge can also draw on the bead a blocker holds back.** Set `drawn_on = "blocked"` and a collapsed bead held back by an open blocker shows the blocker's badge, so a bead waiting on a pull request links to it. The default, `"own"`, changes nothing. The README's gh:pr entry sets it.

**`bdi gates` settles a gate when its pull request leaves draft.** Give a gh:pr gate `awaits=ready_for_review` in its metadata and it closes once the pull request is open and no longer a draft, or merges. A gate without the key settles on merge as before. A gate with any other `awaits` value is reported as one `bdi gates` cannot settle, and stays open.

**Two `bdi gates` instances can split the work by owner.** `[gates] excluded_owners` names owners an instance leaves to the other, and the startup line says which.

**`bdi gates` is gentler with GitHub.** It asks about a repository's gated pull requests in one query, and waits out a rate limit instead of spending the login's budget. With `--listen`, `/healthz` answers 503 while GitHub refuses every read, so a revoked token shows in your readiness probe.

## Maintenance

The plugin's server moves to Effect 4, and the audit skills and docs are refreshed.
