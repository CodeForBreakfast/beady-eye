bdi 0.22.0

Minor release, **0.21.0 → 0.22.0**.

## Highlights

**`bdi listen` is now `bdi watch`, with no alias.** The process that holds every project's beads and serves them on a socket is now called the watcher. The `[listener]` config section is now `[watcher]`, and the default socket `$XDG_RUNTIME_DIR/beady-eye/listener.sock` is now `watcher.sock` in the same directory. If you run a listener, change all three when you upgrade: the command your service manager starts, the config section, and any consumer that names the socket's path. A config that still has a `[listener]` section stops every `bdi` command with ``unknown field `listener` ``, the view included. `bdi listen` is read as a bead id, so under a service manager it exits with "bdi's view needs a terminal". The `watch` and `watch-all` lines a consumer sends keep their names. "Running the watcher" in `docs/configuration.md` has the renamed systemd and launchd units.

**The watcher can pass on bd's event records.** Set `events_journal = true` on a project whose writers all keep bd's events journal. The watcher then sends each record as an `event` line to every consumer watching the bead the record names, ahead of the bead's new state. A record says who made a change and carries the text of a comment. The freshness line's `events` says `off`, `ok` or `unreadable`. Without the key nothing changes. `docs/configuration.md` has the details.

**The watcher holds much less memory on Linux.** It hands freed memory back to the system after each read, so its resident size stays close to what it holds instead of climbing with every consumer it serves. Nothing to do.
