bdi 0.4.0

Minor release, **0.3.0 → 0.4.0**.

## Highlights

**A tracker written either side of April 2026 draws again.** bd spelled a bead's `metadata` as a JSON string until then, and stopped without rewriting the rows it had already stored. A tracker old enough to hold rows from both eras drew nothing at all — not one bad bead, the whole project, reported on its line as a tracker that could not be read. `bdi` now reads that string as the object it spells, and reads a null, a number, or a string spelling something that is not an object as no metadata. If a project of yours has been coming up empty, this release is why it stops. That is [issue #37](https://github.com/CodeForBreakfast/beady-eye/issues/37), and there is nothing to do beyond upgrading.

**A read that will not parse now says which read, and where it stopped.** The old failure was one sentence with nowhere to go from it. It now names the command `bdi` ran and carries the parser's own account of the position it gave up at, so you can run that command yourself and land on the row that broke it.

```
bd answered with something bdi cannot read · bd list · invalid type: null, expected a string at line 1 column 25
```

**Homebrew tracks the release from the day it lands.** `brew install codeforbreakfast/tap/bdi` was reaching a formula somebody had updated by hand, so between a release and that update it installed the previous version and reported success. The release now writes the formula itself, from the same binaries it attaches to the Release. Nothing changes in how you install; the version you get is the one you asked for.

## Breaking: a tracker's reason under `--json`

This one is for you only if something reads `bdi --json`.

An unreachable tracker's reason was a bare string, at `failed_projects[].tracker` and again at `trees[].tracker.unreachable`. It is now an object tagged with `reason`, and a `parse` reason carries `read` and `cause` beside it.

```json
{ "project": "orbital", "tracker": { "reason": "parse", "read": "list", "cause": "invalid type: null, expected a string at line 1 column 25" } }
```

A reader that matched on the old string wants the `reason` field instead.

## Installing

```console
$ brew install codeforbreakfast/tap/bdi
```

`cargo install beady-eye` from crates.io if you would rather compile it. Or pin `github:CodeForBreakfast/beady-eye/v0.4.0` as a flake input and take the package or the overlay. Or take a binary from this page: one per platform, `.sha256` beside each, the Linux ones static. Apple has not been asked to sign the macOS ones, so a copy a browser downloaded needs `xattr -d com.apple.quarantine bdi` first.

The crate is `beady-eye`. The command is `bdi`.

## Maintenance

- The README is written for somebody arriving at `bdi` for the first time, leads its install section with Homebrew, and has a picture of the eye at the top.
- A version bump no longer recompiles every dependency, so a release merge reuses the graph a docs merge built.
- The release publishes on the verdict CI already returned for the commit, rather than checking the same tree a second time.
