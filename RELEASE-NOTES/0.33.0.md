bdi 0.33.0

Minor release, **0.32.1 → 0.33.0**.

## Highlights

**`bdi --beads <bead>` writes the readiness of one bead's dependency tree.** The tree is the bead you name and everything it depends on, followed into other projects' trackers. The document lists the beads ready to start, the gates free to close, and every other unfinished bead with what it still waits on.

**`bdi --beads` takes `--label`, `--type`, `--assignee` and `--parent`.** Each keeps only the beads that match, in the plain listing, in `--ready`'s lists and in a bead's tree. `--parent` keeps every bead beneath the one you name, at any depth.

**Each bead in `bdi --beads` names its parent, and `--brief` leaves descriptions out.** A bead with no parent carries `null`.

**Each bead in `bdi --beads` lists every dependency edge.** Its new `dependencies` field holds the parent edge and every other edge, finished blockers and non-blocking edges included. Each edge gives its type and the other bead's project, id and status, and a bead's tree carries the same field. A parent in another project now names that project, in `parent` and in the bead window.

**A blocker in a project the run did not read no longer counts as open.** `blocked_by` names only the blockers bdi read as unfinished. A blocker it could not read is listed under the bead's `orphaned_dependencies`, and the bead still reads as not ready.

**A change to a tracker costs bd's server a read of what changed.** When a tracker moves, bdi reads only the beads that changed since its last read rather than the whole tracker. A large tracker's server sees far less load from a running bdi or its watcher.

None of this needs anything from you.
